# Micronaut 5.2: no introspection for a record whose static method returns a generated type

On Micronaut Platform 5.2.0 (Core 5.2.8), an `@Introspected` record gets no
bean introspection when one of its static methods returns a type that another
annotation processor generates in the same compilation. Compilation succeeds
with no error or warning; the failure appears at runtime. On Platform 5.1.5
(Core 5.1.15) the same code works.

This project was generated by [Micronaut Launch](https://launch.micronaut.io)
and trimmed to the Micronaut application plugin plus
[RecordBuilder](https://github.com/Randgalt/record-builder), which generates a
`<Record>Builder` class for each record annotated `@RecordBuilder`.

## The two records

- `RecordWithBuilderFactory` declares `static RecordWithBuilderFactoryBuilder named(String)`,
  so a method signature names the generated builder type.
- `RecordWithRecordFactory` is the control: it uses its generated builder only
  inside a method body, and its factory returns the record itself.

`IntrospectionTest` asks for each record's introspection and instantiates it.

## Reproduce

```bash
./gradlew test                            # Platform 5.2.0: RecordWithBuilderFactory fails
./gradlew test -PmicronautVersion=5.1.5   # Platform 5.1.5: both pass
```

On 5.2.0:

```
IntrospectionTest > recordWhoseStaticMethodReturnsAGeneratedTypeIsIntrospected() FAILED
    io.micronaut.core.beans.exceptions.IntrospectionException: No bean introspection available for type [class com.example.RecordWithBuilderFactory]. Ensure the class is annotated with io.micronaut.core.annotation.Introspected
```

| Platform | Core | `RecordWithBuilderFactory` | `RecordWithRecordFactory` |
|---|---|---|---|
| 5.1.5 | 5.1.15 | introspected | introspected |
| 5.2.0 | 5.2.8 | no introspection | introspected |

Processor order does not change the result. Putting RecordBuilder first on the
annotation processor path, with the `annotationProcessorPath` sort the Micronaut
Gradle plugin documents for Lombok, still leaves `RecordWithBuilderFactory`
without an introspection on 5.2.0.

## Impact with Micronaut Data

`@MappedEntity` carries `@Introspected`, so a record entity with such a factory
loses its introspection the same way. In the application where this was found,
16 of 38 entities were affected, all compiling cleanly.

Their repositories were also compiled without their compile-time queries. That
is a separate Micronaut Data 5.2.0 regression with the same trigger, not a
consequence of the missing introspection, and it is not reproduced here.

## Environment

- JDK 25.0.3 (GraalVM)
- Gradle 9.6.0
- Micronaut Gradle plugin 5.0.2
- RecordBuilder 53
