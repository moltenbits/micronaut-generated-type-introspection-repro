# Micronaut: no introspection for records involving a type generated in the same compilation

Two Micronaut Core annotation-processing bugs leave a record without its bean
introspection. Compilation succeeds without a diagnostic identifying the
missing introspection; the failure appears at runtime, with
`IntrospectionException: No bean introspection available for type [...]`. Both are triggered by a type that another
annotation processor generates in the same compilation.

This project was generated by [Micronaut Launch](https://launch.micronaut.io)
and trimmed to the Micronaut application plugin, Micronaut Serialization, and
[RecordBuilder](https://github.com/Randgalt/record-builder), which generates a
`<Record>Builder` class for each record annotated `@RecordBuilder`.

It builds on Micronaut Platform 5.2.1 and imports the Micronaut Core 5.2.14
BOM over it (`micronautCoreVersion` in `gradle.properties`), so it runs on the
latest Core release.

## Reproduce

```bash
./gradlew test
```

On Platform 5.2.1 with Core 5.2.14:

```
HolderIntrospectionTest > serdeableRecordHoldingARecordWhoseStaticMethodReturnsAGeneratedTypeIsIntrospected() FAILED
    io.micronaut.core.beans.exceptions.IntrospectionException at HolderIntrospectionTest.java:13

4 tests completed, 1 failed
```

Other versions:

```bash
./gradlew test -PmicronautVersion=5.1.5 -PmicronautCoreVersion=5.1.15
./gradlew test -PmicronautVersion=5.0.2 -PmicronautCoreVersion=5.0.2
```

## 1. A `@Serdeable` record holding such a record (open)

`SerdeableHolder` is a `@Serdeable` record with no static methods of its own.
Its one component is `SerdeableRecordWithBuilderFactory`, a `@Serdeable`
record whose static factory returns `SerdeableRecordWithBuilderFactoryBuilder`,
the type RecordBuilder generates for it. `SerdeableHolder` gets no
introspection. `IntrospectedHolder`, the control, holds the same kind of record
with `@Introspected` and no Serialization, and is introspected.

| Platform | Core | Serialization | `SerdeableHolder` | `IntrospectedHolder` |
|---|---|---|---|---|
| 5.0.2 | 5.0.2 | 3.0.0 | introspected | introspected |
| 5.1.5 | 5.1.15 | 3.1.1 | no introspection | introspected |
| 5.2.0 | 5.2.8 | 3.2.2 | no introspection | introspected |
| 5.2.1 | 5.2.14 | 3.2.4 | no introspection | introspected |

The cause is in Core's `IntrospectedTypeElementVisitor`. Micronaut
Serialization's visitor postpones `SerdeableHolder` to the next round, because
its component type cannot be fully read until RecordBuilder's generated builder
exists. The other visitors still visit the type in that round, but the visitor
context refuses any output for a postponed type
(`JavaVisitorContext.checkForPostponedOriginalElement`), so writing the
introspection throws `ElementPostponedToNextRoundException`.
`IntrospectedTypeElementVisitor.write` catches it ("next round will redo"), but
by then the type is recorded as processed and its introspection name as
written, so the next round's visit returns without writing it.

## 2. A record whose static method returns a generated type (fixed in Core 5.2.11)

`RecordWithBuilderFactory` declares
`static RecordWithBuilderFactoryBuilder named(String)`, so a method signature
names the generated builder type. On Platform 5.2.0 (Core 5.2.8) it got no
introspection. `RecordWithRecordFactory`, the control, uses its generated
builder only inside a method body. Reported as
[micronaut-core#13586](https://github.com/micronaut-projects/micronaut-core/issues/13586)
and fixed in Core 5.2.11 by
[micronaut-core#13588](https://github.com/micronaut-projects/micronaut-core/pull/13588).
`IntrospectionTest` covers both records and passes on Platform 5.2.1.

Processor order does not change either result. Putting RecordBuilder first on
the annotation processor path, with the `annotationProcessorPath` sort the
Micronaut Gradle plugin documents for Lombok, does not help.

## Impact with Micronaut Data

`@MappedEntity` carries `@Introspected`, so a record entity hit by either bug
has no introspection, and its repository fails when it reads or writes the
entity. In the application where these were found, bug 2 affected 16 of 38
entities on Platform 5.2.0, and bug 1 still affects an entity that holds such a
record, alongside two other `@Serdeable` records, on Core 5.2.14.

The repositories of the entities hit by bug 2 were also compiled without their
compile-time queries. That is a separate Micronaut Data 5.2.0 regression,
[micronaut-data#4064](https://github.com/micronaut-projects/micronaut-data/issues/4064),
fixed in Data 5.2.1, and it is not reproduced here.
